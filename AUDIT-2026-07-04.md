# Perantau Global — Full Platform Audit (2026-07-04)

Read-only audit of the whole stack: security/vulnerability, backend + DB integrity, candidate portal, admin CRM, and the public web funnel (incl. UI/UX vs the low-literacy PMI audience and the documented user journey). Ran 5 specialized agents in parallel; every load-bearing claim was verified against **source code + the live Supabase DB** (`jeadtvxgxmqnsqwxjmhj`), not just docs. Two agent false-positives were caught and dropped (revalidate "path traversal" → actually a route string; slot-fill "count bug" → actually correctly scoped).

## Overall verdict

The platform is **more solid than most 2-month-old products** — the hard things are done right: PII documents are in private buckets with correct owner-scoped RLS, RLS is on every table, admin authorization is airtight (all 43 admin actions gate on `assertAdmin` first), the candidate "done = presence, never `hard_pass`" rule is correct everywhere (no lengkapi dead-end), idempotency and FK-cascade design are careful, and the CV grader is "score not gate" as intended. **There are no critical data-exposure holes.**

The real gaps are three shapes:
1. **A few live bugs shipping right now** (admin inbox silently broken, a PII table readable by anon, orphan CVs accumulating, double-`/bulan` on ad pages).
2. **The funnel + pipeline don't finish the job** — the apply flow forces a password + email-click (the ~50% / measured 33% drop), and the admin pipeline is labels-with-no-data past "screening."
3. **Structural risk with no alarm** — the signup mega-trigger is a single point of failure whose last silent regression went undetected for ~2 weeks, and nothing monitors it.

## Live evidence snapshot (prod, audit time)

- **Funnel leak, quantified:** 1,496 form submissions → **497 (33%) never became a candidate** (never confirmed email). 116 candidates (9%) have no phone.
- **Pipeline barely used past screening:** of 1,461 applications — `applied` 1,083, `screening` 198, `rejected` 168, **`interview` 3**, `voice_screen` 5, `document_check` 1, `briefing` 1, `exit` 2. The stages the pipeline claims to "drive to deployment" have almost no data because there's nothing to capture there.
- **Scale has crossed the 1000-row cap:** applications 1,461 · candidates 1,301 · candidate_documents 1,347 · pending_submissions 1,496 (581 unconsumed) · audit_log 1,264. (Admin read paths already paginate — see "solid".)
- **Orphan PII right now:** 8 CV files > 48h sitting unpurged in `pending-cv`.
- **Affiliate:** 2 active codes, 0 real attributed referrals; the 6 `referral_code_input` values are junk users typed ("BELUMADA", "SENDIRI", phone numbers).

# Per-surface detail (file-anchored)

## Security

**Done well (don't touch):** private `candidate-documents` + `pending-cv` buckets with owner-scoped RLS + signed URLs (no public PII); RLS on every table; all 43 admin actions gate `assertAdmin` first; the flagged authenticated-executable SECURITY DEFINER RPCs are safe (`log_admin_action` enforces `is_admin()` internally; academy RPCs call `_assert_academy_enrollment_owner`; a candidate **cannot** self-mark an enrollment paid — that's service-role-only via `mark_academy_enrollment_paid`); quiz answer keys never leave the server; "CV = score not gate" holds (grade-cv never writes `hard_pass`/`qualifying`); secrets hygiene clean (service role only server-side; CSP/HSTS enforced); `/auth/callback` has no user-controlled redirect.

**Findings:** P1-7 (pending_submissions bypass, High), P2-5 (referral enumeration, Med), P2-4 (xendit amount/HMAC, Med, pre-launch), P0-6 (leaked-password, Low). Rate-limit RPCs are fail-open and trust a spoofable `x-forwarded-for` (Low, defense-in-depth). `/api/revalidate` needs a `slug` allowlist if the secret ever leaks (Low — it's a route string, not a filesystem path).

## Database / backend integrity

**Done well:** idempotency is genuinely correct across the async surface (`ON CONFLICT` + real unique indexes on commission events, enrollments, CV assessments, fit); `update_job_order_slot_filled` recomputes by COUNT (self-healing); FK `ON DELETE` design is careful (children CASCADE, history SET NULL, positions RESTRICT); readiness/completeness/qualifying split is clean with zero references to the dropped legacy schema; migration ledger has no SQL-editor drift (live trigger == migration 0088 byte-for-byte).

**Findings:** P0-4 (unguarded trigger loop, Critical), P1-9 + C2 (no observability, Critical-process), P0-3/H2 (unscheduled purge, High), P2-2/H1 (backfill 800-row blind spot, High), P2-3/H3 (score_pct field-set, Med), M1 (`applications.score` 100% NULL but still selected — drop it), M3 (perf advisors). Note corrections to stale docs: `event_registrations.status` is **NOT** dead (2 values in use); the `0082` filename collision is benign (the second file is the intentionally-unapplied Paspor seed — rename to `0089` when it ships); `xendit-webhook` correctly not deployed yet.

## Candidate portal

**Done well:** core apply→lengkapi→status loop is solid; `pipeline_stage` never leaks (candidate sees 4 friendly outcomes + human-labeled timeline, consistent across all 4 surfaces); "done = presence, never `hard_pass`" verified end-to-end (no lengkapi dead-end); error/404 boundaries exemplary (plain Bahasa, retry, WhatsApp human fallback); server actions return `{ok,error}` inline; mobile-first is real (44–52px targets, bottom sheets, skeletons); akademi security model textbook.

**Findings (all P2-11 bucket unless noted):** `/onboarding` is orphaned dead code (no inbound link; Beranda S1 is the de-facto onboarding); apply wizard "Cek syarat" section renders permanently empty + a dead warning banner (reads broken — remove it, which also shortens the funnel → helps P1-1); Profile "Paspor" stat tile hardcoded `—/Belum mulai` (visibly wrong for enrolled learners); expired magic-link error flashes 1.8s then auto-redirects (slow-connection users miss why); `/auth/whatsapp` is a dead "Segera hadir" sketch (hide until wired); CV re-grade after cert upload is invisible (add a "CV lagi dinilai ulang…" pending state + show the score bump — the one place a progress number is honest AND motivating); the "Pendamping" card shows canned messages with a fake "Online/Baru saja" timestamp — for a scam-fearful audience, simulating a human that isn't there is a trust risk; wire it to the real named-PIC WhatsApp instead. Also: real completeness `%`/progress-ring is a mild "no fake gamification" principle bend — consider demoting to a plain "3 dari 5" fraction.

## Admin CRM

**Done well:** the 1000-cap defense is genuinely handled across analytics, dashboard, candidates, documents, audit-log, CSV export (paginate or exact-count) — the class of bug the old TASKS notes worried about is largely retired; audit logging is a real, well-architected compliance system (log-before-write, throw-on-failure, IP/UA, ~30+ mutations covered); one canonical stage list prevents "Diterima" drift across surfaces; position draft/publish flow fully wired; team owner-protection + anti-lockout real.

**Findings:** P0-1 (inbox constraint bug, High), P1-4 (no pipeline data capture, High), P1-5 (no bulk actions, High), P2-9 (3 audit-log gaps, Med), no new-submission/urgent-doc notification channel (Med — inbox questions are the "sering bikin kandidat batal daftar" ones, discovered only by manual polling; Resend infra already exists), no in-app inbox reply (leave app → Gmail → return), reject captures no reason + no pool-level re-open, applications search is name/phone only while the table shows email (F6 inconsistency), JO-detail candidate list is the one genuinely unbounded fetch left (latent, powers kanban counts). `applications.score` returned by the RPC but never rendered (dead).

## Public web / funnel

**Done well:** the **event flow is the friction gold standard** (3 fields, no password, immediate Zoom link, dual-fired CAPI with dedup) — copy it into apply; anti-abuse solid (honeypot + email/IP rate-limit, fail-open for legit users); Meta cross-domain attribution thoughtfully handled (`_fbc` reconstruction survives the email hop); DB-driven catalog with static fallback; AI-crawler-friendly robots; per-page canonicals; self-hosted fonts (no CLS); returning-user shortcut skips re-signup.

**Findings:** P1-1 (password gate, High), P1-2 (no JobPosting JSON-LD, High-SEO), P1-3 (cek-kesiapan dead-ends warm leads, High), P1-6 (trust: "1998" + retired GTH + no named PIC + placeholder testimonials), P1-8 (sitemap/stats from static not DB), P0-5 (double-`/bulan` + flagship salary). Also: `EditorialHero` uses CSS `background-image` not `next/image` → the LCP hero on every paid LP is unoptimized + unpreloaded (Med perf); `hreflang` advertises retired `/en/*` URLs that 301 to home (remove the `en` branch — site is intentionally ID-only; `en.json` is dead); NAP inconsistency between `organizationJsonLd` and `localBusinessJsonLd` (two addresses/phones); QuickFacts renders raw `salaryNote` producing redundant/overflowing captions; assorted admin-authored `positions.content` hygiene noise (`"180  KWD "`, `"SAR 2000/Month =- 2 years"`, English `/Month` on an all-ID site) — clean via the Position Editor.
