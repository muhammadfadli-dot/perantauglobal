## HIGH findings (8) — with holistic fix judgment

### H1. `application_readiness_view` is SECURITY DEFINER with no row filter → IDOR / PII enumeration
- **Where:** `packages/db/migrations/0053_application_readiness_qualifying.sql:17` (view), `:90-91` (grants).
- **Proven (live role-simulation):** as `authenticated` with a random JWT, `SELECT count(*) FROM application_readiness_view` → **617** (all rows); `SELECT count(*) FROM applications` under the same identity → **0** (RLS blocks). The view bypasses RLS. **`anon` ALSO holds SELECT** (public/bundled key) — wider than first flagged.
- **Impact:** any logged-in candidate (or anyone with the public anon key) can enumerate all 617 applications' `candidate_id` + `position_slug` + `hard_pass`. Real IDOR; privacy breach for a scam-fearful ICP; PDP exposure. (Only 4 columns, no names/phones directly → HIGH not critical.)
- **Fix:** tracked migration `0056`: `ALTER VIEW application_readiness_view SET (security_invoker = true);` + `REVOKE ALL ON application_readiness_view FROM anon;` Then verify `journey.ts` + admin pages still return expected rows; re-prove anon→0, candidate→own-only.
- **Fix judgment: SOUND, do first.** `security_invoker` makes the view honor the caller's existing `applications` RLS (already correct: self-read for candidates, `is_admin()` for admins). Low risk; the only verification needed is that admin reporting still sees all rows (it does — `is_admin()` policy). This is the single highest-value change. Touches **prod DB**.

### H2. Admin home dashboard "Diterima" undercounts (counts only `selected`)
- **Where:** `apps/platform/src/app/(admin)/admin/page.tsx:109` — `if (row.pipeline_stage === "selected")`.
- **Impact:** analytics (`analytics/page.tsx:166`), kanban, and JO board all count `selected|training|deployed|active` (the canonical `ACCEPTED_STAGES` in `journey.ts:39` + `applicationStatus.ts:21`). The **first screen an admin sees** shows fewer "Diterima" than every other surface — two pages disagree on an identically-labeled KPI.
- **Fix:** export one `ACCEPTED_STAGES` constant from `lib/applicationStatus.ts`, import it in dashboard + analytics + kanban + JO detail. (JO detail also adds `trial` — reconcile.)
- **Fix judgment: SOUND, trivial.** Single source of truth kills the drift permanently. Zero risk.

### H3. Split canonical domain (SEO)
- **Where:** `apps/web/src/lib/seo.ts:4` uses `https://dayatalentaglobal.id`; `jsonld.ts:1`, `sitemap.ts:5`, `layout.tsx:6` metadataBase use `https://perantauglobal.com`; `robots.ts:38` points the sitemap at `dayatalentaglobal.id`.
- **Impact:** every page emits a canonical + OG URL on `dayatalentaglobal.id` while the sitemap (hosted, per robots, on `dayatalentaglobal.id`) lists `perantauglobal.com` URLs. Google sees conflicting canonicals → split/diluted indexing, possibly the wrong domain ranked.
- **Fix:** one `SITE_URL` constant (`perantauglobal.com` per project docs) imported everywhere; fix `robots.ts` sitemap URL.
- **Fix judgment: SOUND.** Confirm `perantauglobal.com` is the intended canonical (it is, per CLAUDE.md). Low risk.

### H4. Default OG/share image is an SVG + a missing PNG
- **Where:** `apps/web/src/app/layout.tsx:16` → `/images/og-default.svg`; `seo.ts:26` default → `/og-default.png` (does **not** exist on disk).
- **Impact:** FB/WhatsApp/X/LinkedIn don't render SVG as `og:image` → blank link previews. WhatsApp is the primary share channel for this audience → blank cards when candidates forward a lowongan undercut the anti-calo trust play. Homepage `generateMeta()` emits a 404 `og-default.png`.
- **Fix:** generate a 1200×630 JPG/PNG OG card, reference from `layout.tsx` + `seo.ts`; drop the SVG OG ref.
- **Fix judgment: SOUND.** Needs an image asset (can generate via fal-ai). Low risk.

### H5. Homepage hero presents fabricated "alumni" with hard claims + no disclaimer
- **Where:** `apps/web/src/components/pg/home/HomeHero.tsx:123` — "**Sari, Budi, Rini** + 200 alumni sejak 2024 — semua diberangkatkan resmi." Portrait cards carry name/role/"2025" + a **verified-check badge** (`:181`). The **same three people** are disclaimed as "Komentar contoh — akan diganti cerita kandidat asli sebelum rilis" in `Testimoni.tsx:94` — but the hero (making a *harder* claim) has no disclaimer.
- **Impact:** for a scam-fearful ICP (authenticity convention), the hero asserts these are real placed workers + an unverifiable "+200 alumni" with trust-signalling checkmarks. The codebase itself admits they're placeholders → false placement/headcount claim on the highest-risk surface; credibility + legal exposure.
- **Fix (needs your call):** (a) remove the named-people + "+200 alumni … semua diberangkatkan resmi" hard claim and add the same "contoh/ilustrasi" disclaimer; or (b) swap to real consented alumni photos+names; don't show verified-checkmarks on illustrative people.
- **Fix judgment: SOUND but content decision is yours.** Code change is trivial; *which* direction (remove-claim vs real-photos) is a brand/content call only you can make.

### H6. Profile page shows fabricated "Paspor 40% / 3 modul lagi" as a real stat
- **Where:** `apps/platform/src/app/(candidate)/profile/page.tsx:194` — hardcoded `value="40%" caption="3 modul lagi"` in the **same 4-tile grid** as three genuine DB-computed stats (Lamaran/Dokumen/Data diri).
- **Impact:** a candidate who never opened a Paspor module sees fabricated personal progress indistinguishable from real progress, with **no disclaimer** (unlike the `/paspor` tab, which has "Demo konten"). Trust hazard + implies certification progress not started.
- **Fix:** until `paspor_courses` tables (0040-0042, drafts) ship, replace with a neutral CTA (`value="—" caption="Belum mulai"`) or remove the tile.
- **Fix judgment: SOUND, trivial.** Zero risk.

### H7. Job order status & notes cannot be edited anywhere (broken core flow)
- **Where:** `apps/platform/src/app/(admin)/admin/job-orders/[id]/page.tsx:159` — "Edit JO" links to `/admin/job-orders/[id]/edit`, which **does not exist** (404). `StatusControls` + `NotesField` are defined but **never mounted** (orphaned). The `updateJobOrderStatus` / `updateJobOrderNotes` actions exist and work — only the UI wiring is missing.
- **Impact:** admins can never move a JO open→filled/closed/cancelled or edit notes/slots/deadline. Stale "open" JOs keep showing on public `/lowongan` and in pickers. JO is the pipeline tracker (lamaran-vs-JO model) → lifecycle management is effectively missing.
- **Fix:** mount `StatusControls` + `NotesField` in the detail page's "Aksi cepat" panel (fastest), or build the `[id]/edit` route. Actions already exist.
- **Fix judgment: SOUND.** Mounting in-place is the lower-risk, faster path. Low risk.

### H8. Position Editor: Konten-tab auto-save silently clobbers Media & SEO edits
- **Where:** `apps/platform/src/components/admin/MediaSeoTab.tsx:71` dispatches `pg-editor-state` **without** a `content` field; `PositionEditorShell` never ingests external content, so its next `saveDraft(slug, content)` (full overwrite, `actions.ts:150`) writes back stale media/seo. Sync is one-directional (Konten→Media survives; Media→Konten is lost).
- **Impact:** admin sets hero/OG/meta in Media&SEO (auto-saved), switches to Konten, edits anything → the 30s auto-save persists `content` **without** media/seo, silently reverting the assets. On Publish, the public page loses them.
- **Fix:** make the event bus bidirectional (MediaSeoTab dispatches the **full merged** content; Shell reconciles), or lift `content` to a single owner (`PositionEditorShell`) and have MediaSeoTab edit through it.
- **Fix judgment: SOUND; lift-state is the durable fix.** Medium risk (touches the editor state machine) — verify with a save/switch/publish cycle.
